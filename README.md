# YouTube AI Studio

A full-stack web app for YouTube creators. Paste a YouTube link to fetch its metadata, then generate optimized **titles, descriptions, tags and a summary** with AI — using either an OpenAI-compatible LLM of your choice or a built-in rule-based generator.

## Features

- Add any YouTube video by URL (watch, shorts, youtu.be, embed, live).
- Fetch rich metadata via the **YouTube Data API** when a key is configured, with a key-less **oEmbed** fallback.
- One-click **AI analysis**: 5 title options, a ready-to-publish description, up to 12 tags and a summary.
- **LLM-first**: when `USER_LLM_API_KEY` and `USER_LLM_BASE_URL` are set, analysis is generated by your own OpenAI-compatible endpoint (DeepSeek, OpenAI, etc.). Otherwise the rule-based generator kicks in automatically and the UI shows which provider was used.
- SQLite persistence (built-in `node:sqlite`, no native build step).
- Clean, responsive dark UI built with React + Vite + TypeScript.

## Getting started

Requirements: **Node.js >= 22** (uses the built-in `node:sqlite` module).

```bash
# 1. Install dependencies
npm install

# 2. Configure environment (optional, see .env.example)
cp .env.example .env
```

The app works out of the box with no configuration (rule-based AI + oEmbed metadata). To unlock the full experience, set values in `.env`:

| Variable            | Purpose                                                        |
| ------------------- | -------------------------------------------------------------- |
| `YOUTUBE_API_KEY`   | YouTube Data API v3 key for full metadata (views, likes, duration). Optional. |
| `USER_LLM_API_KEY`  | API key for your OpenAI-compatible LLM provider. Optional.     |
| `USER_LLM_BASE_URL` | Base URL of the LLM provider, e.g. `https://api.deepseek.com/v1`. |
| `USER_LLM_MODEL`    | Model name, default `deepseek-chat`.                            |
| `PORT`              | API port, default `3001`.                                       |

If the LLM env vars are absent, or an LLM call fails, the app falls back to the rule-based generator and flags the fallback in the UI.

## Development

```bash
npm run dev          # starts API (localhost:3001) + Vite dev server (localhost:5173) together
```

The Vite dev server proxies `/api/*` to the backend, so the browser only ever talks to one port.

## Production

```bash
npm run build        # type-checks + builds server (dist/) and web (dist/)
npm start            # runs the built API server
```

The built web assets are served separately (e.g. by any static host or `npm run preview --workspace web`); the API serves only `/api/*`.

## Quality gates

```bash
npm run typecheck    # tsc strict for server + web
npm run lint         # ESLint (typescript-eslint)
npm test             # Vitest unit + integration tests
npm audit            # dependency audit (should report 0 vulnerabilities)
```

## API

| Method | Endpoint                    | Description                                |
| ------ | --------------------------- | ------------------------------------------ |
| GET    | `/api/health`               | Service + provider status                  |
| GET    | `/api/videos`               | List videos (with `hasAnalysis` flag)      |
| POST   | `/api/videos`               | Add a video by URL `{ "url": "..." }`      |
| GET    | `/api/videos/:id`           | Video detail + latest analysis             |
| DELETE | `/api/videos/:id`           | Delete a video                             |
| POST   | `/api/videos/:id/analyze`   | Generate + store AI analysis               |
| GET    | `/api/videos/:id/analysis`  | Latest analysis for a video                |

## Notes

- **AI keys are your own.** The app never uses keys from the runtime environment; it only reads the `USER_LLM_*` variables you define yourself in `.env`.
- The rule-based summary is generated from video metadata (title, channel, stats), not from the transcript — it is labelled as such in the UI.
